# Phase 2 採寸精度向上 改善計画

Phase 1 のヒューリスティック採寸（マスク行幅プロファイル + 基準実測値1点）は
「動画1本だけで完結する」体験を優先した最小実装であり、以下の3つの誤差要因を
本質的に解決できていない。

1. **基準値の手入力に依存**: 出品者が1項目だけ実測して入力する前提のため、
   その入力自体のブレ（測り方の個人差）がすべての推定値に伝播する
2. **形状ヒューリスティックの限界**: 「行ごとの最大幅」で肩幅・袖丈を近似しており、
   生地のたわみ・シワ・重なりを衣類の輪郭と誤認しうる
3. **クロッチポイント未検出**: ボトムスは平置き時に前後の脚が重なるため、
   マスク外形だけでは股上・股下の起点を特定できない

Phase 2 では以下を優先度順に実施する。

## 優先度1: 基準マーカーによる自動スケール取得

**課題**: 出品者の手入力実測値の精度が全体の精度の上限になっている。

**対策**: 撮影時にA4用紙やクレジットカードサイズの基準カード（既知の実寸）を
画面内に写し込んでもらい、OpenCVの ArUco / チェッカーボード検出で
自動的に cm/px スケールを算出する。これにより:
- 出品者の手入力ミスを排除できる
- 動画内でカメラが動いても複数フレームでスケールを再検証・平均化できる

実装イメージ: `services/calibration.py` に `ArucoCalibrationService` を追加し、
`SasagePipeline` で「基準マーカー検出成功時は自動スケール、失敗時は現行の
手入力フォールバック」という二段構えにする（既存フローを壊さない）。

**工数目安**: 中（OpenCV ArUco自体は標準機能。UI側で「基準カードを一緒に撮影」という
撮影ガイドの追加が必要）

## 優先度2: 衣類専用キーポイント検出モデルの導入

**課題**: 行幅プロファイルという幾何ヒューリスティックは「肩点」「袖口点」
「股点」のような意味のある特徴点を直接検出していないため、変則的な形状
（オーバーサイズ、ドロップショルダー等）で誤差が拡大する。

**対策**: DeepFashion2 等の衣類ランドマーク検出データセットで学習された
キーポイント検出モデル（またはSAMのマスク＋幾何的後処理を組み合わせたモデル）を
`MeasurementService` のバックエンドとして追加する。カテゴリごとに検出する
キーポイント集合を定義し、`measurement_standards.py` の `phase1_supported` を
`phase2_supported_by_model` に置き換えていく。

**工数目安**: 大（学習済みモデルの選定・検証、推論環境の構築、Phase1ヒューリス
ティックとの精度比較が必要）

## 優先度3: クロッチポイント検出によるボトムス股上・股下対応

**課題**: `measurement_standards.py` で `phase1_supported=False` としている
股上・股下・わたり幅は、ボトムス採寸で最も需要が高い必須項目である。

**対策**: 優先度2のキーポイントモデルで股点を直接検出するのが本命だが、
つなぎとして以下のヒューリスティック拡張も検討する:
- 前後の脚が重なる境界に生じる**折り目の影**をエッジ検出し、股点候補とする
- 複数アングル動画（後述）で、脚を軽く開いた状態のフレームがあれば
  マスクが二股に分かれる瞬間を検出し、そこから股点を特定する

**工数目安**: 中〜大（ヒューリスティック拡張は中、モデルベースは優先度2と共通）

## 優先度4: マスク精度そのものの向上（SAM導入）

**課題**: 現行の `rembg`（背景がシンプルな場合）/ `GrabCut`（フォールバック）は
袖口・裾などの細部でマスクがギザギザになりやすく、幅プロファイルにノイズが乗る。

**対策**: Segment Anything (SAM) をバックエンドとして追加し、
`background_removal.py` の `BackgroundRemover` インターフェースに
`SAMBackgroundRemover` を実装する（既存の抽象化のおかげでパイプライン側の
変更は不要）。

**工数目安**: 中（SAMのモデルサイズ・推論コストとのトレードオフを検証する必要あり）

## 優先度5: 精度検証の仕組み化（ゴールデンセット）

**課題**: 現状、採寸精度を定量評価する仕組みがない（Phase1では合成データでの
動作確認のみ）。

**対策**: 実際の古着 10〜20点について、メジャーによる手動実測値と動画を
セットで収集し、`backend/tests/golden/` のような形でゴールデンセットとして
保持する。CI で「AI推定値 vs 手動実測値」の平均絶対誤差(MAE)・誤差率を
項目別・カテゴリ別に算出し、`docs/PROGRESS.md` に定点観測として記録する。
これにより優先度1〜4の各施策が実際に精度を改善したかを客観的に判断できる。

**工数目安**: 小〜中（データ収集が最大のボトルネック。実店舗・出品者の協力が必要）

## 優先度6: 撮影ガイドによる入力品質の底上げ（UI改善）

**課題**: 衣類がシワなく真っ直ぐ平置きされているかどうかで誤差が大きく変わるが、
現行UIは撮影方法を指示していない。

**対策**: Streamlit / 将来のNext.js UIに「撮影ガイド枠」「NG例（斜め撮影・
シワが寄っている等）」を表示し、動画アップロード前にセルフチェックできるようにする。
モデル改善より低コストで即座に効果が見込める施策のため、優先度2〜4と並行して
早期に着手する。

**工数目安**: 小

---

## まとめ: 着手順序の推奨

1. （即着手可・低コスト）優先度6: 撮影ガイドUI
2. （即着手可・効果大）優先度5: ゴールデンセット構築開始（データ収集と並行してCI基盤を先に作る）
3. 優先度1: 基準マーカー自動スケール
4. 優先度4: SAM導入によるマスク精度向上
5. 優先度2・3: キーポイント検出モデル導入（股上・股下対応も含む本命施策）

優先度1・4は既存の抽象化（`BackgroundRemover`, `MeasurementService`）に
新しい実装を追加するだけで済むため、既存コードへの影響を抑えつつ段階的に
精度を上げられる。
