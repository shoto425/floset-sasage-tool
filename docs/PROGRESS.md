## 2026-07-06 Phase 1 (MVP) 進捗報告

### 完了したこと
- 全体アーキテクチャ・フォルダ構造・データモデルを設計（`docs/ARCHITECTURE.md`, `backend/app/models/schemas.py`）
- Phase 1 コアパイプラインを実装し、動画1本から下記を一括生成できる状態にした
  - フレーム抽出（鮮明度 + pHashによる構図重複排除）
  - 背景除去 → 白背景平置きJPEG生成（rembg / GrabCutフォールバックを自動切替）
  - 採寸推定（基準実測値1点 + マスク形状比率、肩幅・身幅・着丈・袖丈）
  - 状態検品（OpenCVヒューリスティックによるエッジ密度・明度異常の検出、接写推奨箇所の提示）
  - Instagram / EC原稿生成（Claude API連携 + APIキー未設定時のテンプレートフォールバック）
  - 商品ごとのZIP自動生成（JPEG群 + measurements.json + condition.md + copy.md + summary.json）
- FastAPI エンドポイント (`POST /products/process`, `GET /products/{id}`, `GET /products/{id}/zip`) を実装
- Streamlit MVP UI（動画アップロード→結果確認→ZIPダウンロード）を実装
- pytest によるユニットテスト（採寸ロジック・画像合成・ZIP梱包）を追加

### 動作確認状況
- `pytest`: 4件のユニットテストがすべて成功
- 合成動画（OpenCVで生成したダミー動画）を使い、パイプライン関数呼び出し・FastAPI経由の
  HTTPリクエスト（multipartアップロード → 処理 → ZIPダウンロード）の両方で end-to-end 動作を確認済み
- `rembg`（背景除去の第一候補）は本開発環境ではモデルダウンロードを伴うため未インストール／未検証。
  未インストール時は自動的に GrabCut フォールバックへ切り替わることを確認済み
- Claude API（`llm_backend=claude`）は API キー未設定のため未検証。未設定時に
  テンプレートフォールバックへ正しく切り替わることを確認済み
- 実際のスマートフォン撮影動画・実物の古着でのフル検証は未実施（次フェーズの確認事項）

### 既知の制約・精度に関する注意点
- 採寸はカメラキャリブレーション無しの近似値。出品者が1項目（例: 着丈）を実測して
  入力する前提。精度は「参考値」レベルで、Phase 2 で MediaPipe / SAM によるキーポイント
  検出に置き換える予定
- 状態検品はエッジ密度・明度の統計的異常検知であり、生地の柄やシワを傷と誤検知する
  可能性がある。最終判断は出品者による目視確認を前提とする文言をZIP内レポートに明記済み
- 現在は同期処理（アップロード即処理）。動画が長時間・高解像度になる場合は
  Phase 2 でジョブキュー化が必要
- 結果の保持は現状インメモリ（`_results` dict）。プロセス再起動で消えるため、
  永続化が必要な場合は Phase 2 で DB 化する
