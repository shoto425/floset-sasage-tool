## 2026-07-06 Claude API 精度検証（合成データ） 進捗報告

### 完了したこと
- ユーザーより提供されたAnthropic APIキーで疎通確認・検証を実施
  （キーはリポジトリには一切コミットせず、環境変数として一時利用のみ。
  チャット上に平文で共有されたキーのため、検証後のローテーションを推奨済み）
- 初回はアカウントのクレジット残高不足で 400 エラー（`Your credit balance is
  too low`）となり失敗。ユーザーがクレジットを追加後、再試行して疎通成功
- 実店舗の古着動画・画像が本環境に存在しないため、**合成画像7点**
  （control 2点 + 傷/汚れ/色落ち等を意図的に描き込んだもの5点）で代用検証を実施。
  再利用可能な検証ハーネスとして `scripts/validate_llm.py` を追加（pytestには含めず、
  APIキーを設定して手動実行する想定）
- 検証結果を踏まえ、`condition_inspection_llm.py` のプロンプトを改善
  （`location_hint` の語彙を「肩/袖/袖口/衿/身頃/裾/ポケット/ウエスト/もも」に
  緩やかに制約し、出力の一貫性を向上）

### 検証結果（詳細）

**テストデータ**: 無地Tシャツ×2（control、傷なし）、穴あきTシャツ、ほつれシャツ、
色落ちデニム、シミ付きスカート、破れジャケットの計7点。いずれもOpenCV/PILで
生成した単色矩形ベースの合成画像であり、**実際の生地・シワ・縫い目を含まない**。

**Vision状態検品 (`LLMConditionInspector`, model=`claude-sonnet-5`)**:
| 指標 | 結果 |
|---|---|
| 傷ありサンプルでの「何らかの異常」検出率 | 5/5（複数回実行でも安定） |
| 傷ありサンプルでの傷の"種類"の正しい言語化（穴/ほつれ/シミ/色ムラ/破損） | 5/5 |
| controlサンプルでの誤検知（false positive） | 0/2（複数回実行でも安定） |
| 自動採点スクリプトの厳密キーワード一致率 | 4〜6/7（実行ごとに変動） |

自動採点スクリプトのスコアが実行ごとに4〜6/7とブレたため、生の出力（`raw_issues`）を
目視で確認したところ、**すべての傷は種類・重大度ともに正しく言語化されていた**。
スコアがブレた原因は以下の2点で、いずれもモデルの検出精度ではなく検証ハーネス側の
問題であることを確認済み:
1. 自動採点のキーワード辞書が狭すぎた（例: 色落ちを「色ムラ・変色」と表現された
   ケースを「色落ち/色あせ/退色」という辞書でマッチできなかった）
2. 合成画像の作り込みが粗く、袖と肩の境界が視覚的に曖昧な箇所に穴を描画したため、
   モデルが「左肩」と回答（意図は「左袖」）した — 縫い目・生地の質感がある実物写真では
   起きにくいと予想される、合成データ特有の限界

上記1つ目の問題を受けて `location_hint` の語彙をプロンプトで緩やかに制約したところ、
出力が「左肩」「裾」「身頃中央」のように安定した語彙に収束することを確認（複数回実行）。

**原稿生成 (`CopywritingService`, `llm_backend=claude`)**:
| 指標 | 結果 |
|---|---|
| LLMバックエンドでの生成成功（フォールバックなし） | 7/7 |
| JSON形式の解析成功 | 7/7 |

生成された原稿は検出済みの状態（傷・色落ち等）を自然に本文へ反映しつつ、
「ヴィンテージ古着ならではの表情」といった売り言葉でバランスを取る内容になっており、
ハッシュタグも商品カテゴリ・ブランド有無に応じて適切だった。例（穴ありTシャツ）:

> 【古着入荷】ブランド不明のヴィンテージTシャツ🌿
> 左肩・襟下あたりに円形の穴がありますが、それも味わいとして楽しめる一枚。
> ダメージ古着好きさんにおすすめです。

**コスト・レイテンシ（参考値、精密計測ではない）**: 7商品 × (Vision検品1回 +
原稿生成1回) = 14 API呼び出しで実行時間 約110秒（平均 約7〜8秒/呼び出し）。

### 既知の制約・精度に関する注意点
- 今回の検証は**合成画像**によるものであり、Claude API連携・プロンプト設計が
  意図通り機能することは確認できたが、**実際の古着写真に対する精度を保証するもの
  ではない**。実物は生地の質感・シワ・柄・照明条件が合成画像よりはるかに複雑であり、
  過検知・見逃しの傾向は実データでの再検証まで未知数
- 自動採点ハーネス（`scripts/validate_llm.py`）のキーワード一致は簡易的な近似指標。
  今回のように辞書の狭さや合成データの曖昧さで簡単にブレるため、実データでの
  再検証時は人手によるレビューを主、自動採点を補助として使うこと
- ユーザーは今後、実際の古着動画で再検証予定（本セクションはその前段の
  「合成データでの疎通・integration確認」という位置づけ）

### 次のフェーズでやること
- 実際の古着動画・画像が用意でき次第、`scripts/validate_llm.py` の要領で
  （合成データではなく実データを使い）再検証し、本ドキュメントに追記
- 自動採点ハーネスのキーワード辞書を拡充する、またはLLM-as-judge方式に置き換える
  （表記ゆれに強くするため）
- Vision検品を `SASAGE_CONDITION_BACKEND=llm_vision` として本採用するかは、
  実データでの精度確認後に判断（現状デフォルトは `heuristic` のまま）

### 確認したいこと（意思決定が必要な事項）

### 既知の制約・精度に関する注意点
- 採寸はカメラキャリブレーション無しの近似値。出品者が1項目（例: 着丈）を実測して
  入力する前提。精度は「参考値」レベルで、Phase 2 で MediaPipe / SAM によるキーポイント
  検出に置き換える予定
- 状態検品はエッジ密度・明度の統計的異常検知であり、生地の柄やシワを傷と誤検知する
  可能性がある。最終判断は出品者による目視確認を前提とする文言をZIP内レポートに明記済み
- 現在は同期処理（アップロード即処理）。動画が長時間・高解像度になる場合は
  Phase 2 でジョブキュー化が必要
- 結果の保持は現状インメモリ（`_results` dict）。プロセス再起動で消えるため、
  永続化が必要な場合は Phase 2 で DB 化する
